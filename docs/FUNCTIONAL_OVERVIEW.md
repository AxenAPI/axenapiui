# Описание разделов приложения

Этот документ описывает ключевые разделы и экраны приложения с точки зрения их функциональных возможностей и бизнес-логики.

## Страница «Моделирование» (`/`)

Это основной инструмент визуального проектирования в приложении. Здесь пользователи могут построить диаграмму своей асинхронной архитектуры (`eventGraph`), которая служит главным проектным документом.

> **Примечание:** На текущий момент, сами диаграммы (`eventGraph`) еще не хранятся в Git. Эта функциональность находится в разработке.

### Основные возможности

- **Панель компонентов:** Библиотека узлов (сервисы, топики, схемы), которые можно перетаскивать на холст.
- **Холст для диаграмм:** Основная область для размещения и соединения узлов, визуализирующая потоки данных и связи между компонентами.
- **Редактирование свойств:** Возможность задавать детальные параметры для каждого узла (например, определить схему данных для топика).

## Страница «Документация» (`/documentation`)

Это основной экран для работы с технической документацией, которая хранится в Git-репозитории.

### Основные возможности

- **Навигация по репозиторию:** Пользователь может просматривать структуру папок и файлов репозитория в виде дерева.
- **Редактирование документации:** Приложение предоставляет полнофункциональный MDX-редактор для изменения `.md` файлов с функцией автосохранения.
- **Управление файлами:** Прямо из интерфейса можно создавать, удалять и переименовывать файлы и папки.
- **Интеграция с Git:** Раздел предоставляет полный цикл работы с Git:
  - **Выбор веток:** Возможность просматривать и переключаться между существующими ветками.
  - **Создание веток:** Возможность создавать новые ветки для внесения изменений.
  - **Публикация:** Кнопка для быстрой публикации изменений в виде Merge Request в удаленный репозиторий.

## Страница «Менеджер репозиториев» (`/repository-manager`)

Этот раздел является точкой входа для управления проектами. Он позволяет пользователям подключать к приложению локальные Git-репозитории, которые затем используются в других разделах для моделирования и ведения документации.

### Основные возможности

- Добавление новых репозиториев путем указания пути к локальной папке.
- Просмотр и фильтрация списка всех подключенных репозиториев.
- Удаление репозиториев из приложения.

## Страница «Редактор JSON» (`/editor`)

Этот раздел предоставляет утилиты для работы с JSON и JSON Schema — фундаментальными частями любого API-контракта. Он помогает разработчикам создавать и проверять схемы на основе реальных данных.

### Основные возможности

- Генерация JSON Schema из предоставленного JSON-объекта.
- Генерация примерного JSON-объекта из предоставленной JSON Schema.
- Визуальное представление сгенерированных схем и объектов.

## Прочие возможности и интеграции

Помимо основных страниц, приложение включает в себя ряд сквозных функций и интеграций.

### Генерация артефактов

Хотя часть функций генерации вынесена на страницу "Редактор JSON", приложение также поддерживает:

- **Генерацию спецификаций OpenAPI** (`JSON`, `YAML`).
- **Генерацию кода** для продюсеров и консьюмеров на основе контрактов.
- **Построение различных диаграмм** (архитектура, потоки данных).

### Автоматизация и Тестирование

- **Интеграция со Swagger UI:** Позволяет удобно тестировать API прямо из приложения.
- **MCP (Master Control Program):** Внутренняя система, которая умеет автоматически создавать задачи в трекере на основе написанной в приложении документации (еще не напрямую из приложения).
