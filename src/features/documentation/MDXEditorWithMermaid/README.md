# MDXEditorWithMermaid

Компонент редактора Markdown с расширенными возможностями для технической документации.

## Возможности редактора

### Базовая разметка Markdown

- **Заголовки** — поддержка уровней H1, H2, H3
- **Списки** — нумерованные и маркированные
- **Цитаты** — блоки цитирования
- **Ссылки** — вставка и редактирование гиперссылок
- **Изображения** — вставка изображений с автодополнением URL
- **Таблицы** — создание и редактирование таблиц
- **Горизонтальные линии** — разделители контента
- **Форматирование текста** — жирный, курсив, подчеркивание, зачеркивание, код

### Блоки кода

- **Подсветка синтаксиса** — поддержка множества языков программирования
- **CodeMirror** — продвинутый редактор кода с нумерацией строк
- **Поддерживаемые языки:**
  - Plain Text
  - JavaScript / TypeScript (ts, tsx)
  - JSON
  - YAML
  - HTML / CSS
  - Bash
  - Python
  - SQL
  - Dockerfile
- **Кастомные блоки** — пустые блоки для специальных целей

### Диаграммы

- **Mermaid** — интерактивное создание диаграмм (flowchart, sequence, class, state, ER и др.)
- **PlantUML** — поддержка UML-диаграмм
- **Предпросмотр в реальном времени** — визуализация диаграмм при редактировании

### Директивы MDX

- **Admonitions** — блоки примечаний (note, tip, warning, danger)
- **Frontmatter** — метаданные документа в формате YAML

### Автоматическая нормализация

- **HTML-теги** — автоматич��ское преобразование `<br>` → `<br />`, `<hr>` → `<hr />`
- **Code blocks** — нормализация неподдерживаемых языков
- **Превентивная обработка** — при инициализации, blur, переключении режимов

### Обработка ошибок

- **Локализация** — сообщения об ошибках на русском языке
- **Типы уведомлений:**
  - `info` — для автоисправляемых ошибок (теги `<br>`, `<hr>`)
  - `error` — для ошибок, требующих внимания
- **Позиционирование** — указание строки и колонки ошибки
- **Автоисправление** — автоматическое устранение распространенных ошибок

### Режимы редактирования

- **Rich text** — визуальное редактирование с форматированием
- **Source mode** — редактирование исходного Markdown-кода
- **Diff mode** — сравнение версий документа

### Toolbar

- **Кастомизируемая панель инструментов** — кнопки для всех операций форматирования
- **Быстрые команды** — markdown shortcuts для ускорения работы

### Плагины @mdxeditor/editor

Редактор использует следующие плагины:

1. **toolbarPlugin** — панель инструментов с кнопками форматирования
2. **directivesPlugin** — поддержка директив (Admonitions)
3. **listsPlugin** — нумерованные и маркированные списки
4. **quotePlugin** — блоки цитирования
5. **headingsPlugin** — заголовки H1-H3
6. **linkPlugin** — вставка ссылок
7. **linkDialogPlugin** — диалог редактирования ссылок
8. **imagePlugin** — вставка изображений с автодополнением
9. **tablePlugin** — создание и редактирование таблиц
10. **thematicBreakPlugin** — горизонтальные линии
11. **frontmatterPlugin** — YAML frontmatter
12. **codeBlockPlugin** — блоки кода с кастомными дескрипторами
13. **codeMirrorPlugin** — редактор кода с подсветкой синтаксиса
14. **diffSourcePlugin** — переключение между rich text и source mode
15. **markdownShortcutPlugin** — быстрые команды клавиатуры

## Техническая реализация

### Решение проблемы с тегом `<br>`

### Проблема

MDX парсер требует, чтобы все HTML-теги были либо:

- Самозакрывающимися: `<br />`, `<hr />`
- Парными: `<div>...</div>`

Незакрытые теги `<br>` вызывают ошибку парсинга с сообщением на английском языке.

### Решение

Реализовано автоматическое исправление и локализация ошибок:

#### 1. Автоматическая нормализация HTML-тегов

**Файл:** `utils/normalizeHtmlTags.ts`

Функция `normalizeHtmlTags()` автоматически заменяет:

- `<br>` → `<br />`
- `<hr>` → `<hr />`

Работает с любым регистром (`<BR>`, `<Br>`) и обрабатывает множественные вхождения.

```typescript
const normalized = normalizeHtmlTags(markdown);
// "Строка 1<br>Строка 2" → "Строка 1<br />Строка 2"
```

#### 2. Локализация сообщений об ошибках

**Файл:** `utils/formatParseError.ts`

Функция `formatParseError()` переводит сообщения об ошибках парсинга на русский язык и извлекает номера строк/колонок:

**Поддерживаемые типы ошибок:**

1. **Незакрытые теги:**
   - `Expected a closing tag for '<br>'` → "Обнаружен незакрытый тег <br> (X:Y). Используйте <br /> или экранируйте символы \<br>"
   - `Expected a closing tag for '<hr>'` → "Обнаружен незакрытый тег <hr> (X:Y). Используйте <hr /> или экранируйте символы \<hr>"
   - Любые другие незакрытые теги

2. **Неожиданные символы:**
   - `Unexpected character '@'` → "Обнаружен неожиданный символ "@" (X:Y) в разметке"

3. **Отсутствующие закрывающие теги:**
   - `Expected corresponding closing tag for '<div>'` → "Ожидается закрывающий тег </div> (X:Y)"

4. **Неожиданный конец файла:**
   - `Unexpected end of file` → "Неожиданный конец файла (X:Y). Ожидается закрывающий тег </tag>"

5. **Синтаксические ошибки:**
   - `Expected '>' before end` → "Ожидается ">" (X:Y). Проверьте правильность разметки"
   - `Unexpected token` → "Неожиданный токен (X:Y) в разметке"

6. **Внутренние ошибки парсера:**
   - `Cannot read properties of undefined` → "Внутренняя ошибка парсера (X:Y). Проверьте корректность разметки"

**Форматы позиций:**

- `(61:141-61:145)` → `(строка 61:141-61:145)`
- `(10:5)` → `(строка 10:5)`
- `L1:C1` → `(строка 1:1)` (преобразуется в стандартный формат)

**Скрытие встроенного сообщения:**

Встроенное сообщение об ошибке внутри редактора скрывается программно через `useEffect` в `MDXEditorWithMermaid.tsx`:

- Поиск элементов с классом `markdownParseError` (динамический класс библиотеки)
- Установка `display: none` через inline-стили
- `MutationObserver` отслеживает динамическое добавление элементов ошибок в DOM

Отображается только кастомное уведомление сверху редактора.

#### 3. Визуальное отображение ошибок

**Файл:** `ui/ParseErrorNotification.tsx`

Компонент отображает локализованное сообщение об ошибке с инструкциями для пользователя.

#### 4. Интеграция в редактор

**Файл:** `ui/MDXEditorWithMermaid.tsx`

Обработчик `onError` в компоненте `MDXEditor`:

1. Перехватывает ошибку парсинга
2. Локализует сообщение об ошибке
3. Автоматически исправляет HTML-теги
4. Обновляет содержимое редактора

```typescript
onError={({ error, source }) => {
  // Показываем локализованное сообщение
  const localizedError = formatParseError(error);
  editorModel.events.parseErrorOccurred(localizedError);

  // Автоматически исправляем
  let fixed = normalizeHtmlTags(source);
  fixed = normalizeCodeBlocks(fixed, CODE_BLOCK_LANGUAGES);

  if (editorRef.current) {
    editorRef.current.setMarkdown(fixed);
  }
}}
```

#### 5. Превентивная нормализация

**Файл:** `hooks/useEditor.tsx`

HTML-теги нормализуются автоматически:

- При инициализации редактора
- При потере фокуса (blur)
- При переключении режимов редактирования

```typescript
let normalized = normalizeHtmlTags(markdownContent);
normalized = normalizeCodeBlocks(normalized, CODE_BLOCK_LANGUAGES);
```

### Поведение

1. **Вставка `<br>`**: Автоматически заменяется на `<br />`, пользователь видит корректный результат
2. **Вставка `\<br>`**: Экранированные символы остаются как есть, отображаются как текст
3. **Вставка `<br />`**: Уже корректный тег, не изменяется

### Архитектура

Решение следует FSD (Feature-Sliced Design):

- `model/` — Effector store для состояния ошибок
- `utils/` — Чистые функции для нормализации и форматирования
- `ui/` — React компоненты для отображения
- `hooks/` — Связка UI и бизнес-логики

Все сайд-эффекты изолированы в хуках и обработчиках событий.
