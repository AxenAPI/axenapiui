# Описание схемы процесса поиска (`search-flow.drawio`)

Данная схема иллюстрирует UI-процесс поиска по документам, построенный на тех же принципах FSD (Feature-Sliced Design) и Effector, что и остальные части приложения. Она описывает основной сценарий: от ввода запроса до отображения результатов и перехода к документу.

## Легенда элементов схемы

- **Терминатор (капсула)**: `Gate / Mount` (Начало/Конец страницы/виджета).
- **Ромб**: `Feature` (Действие пользователя).
- **Скругленный прямоугольник**: `Бизнес модель` (Effector-модель: stores, events, effects).
- **Прямоугольник**: `Entity` (UI-компонент, View).
- **Облако**: `Запрос` (Внешний API-запрос, effect).
- **Стрелка**: `Event / sample` (Поток данных, триггер).

## Сценарий работы

Сценарий описывает полный цикл взаимодействия пользователя с функцией поиска, разделенный на логические этапы.

### 1. Начальная загрузка страницы

1.  **Монтирование (`Открытие`):** Пользователь открывает страницу "Документация". Срабатывает `Gate.open` компонента страницы.
2.  **Загрузка дерева (`Модель страницы` -> `Document Tree UI`):** Модель страницы инициирует событие **"Загрузка дерева"**. UI-компонент дерева, в свою очередь, обращается к `getDocumentsApi` для получения и отображения начальной структуры каталогов.

### 2. Активация и выполнение поиска

1.  **Ввод запроса (`Search` -> `Search Input Model`):** Пользователь вводит текст в поле поиска. Модель `Search Input Model` обновляет свой внутренний стор `$searchQuery`.
2.  **Передача запроса оркестратору (`Search Input Model` -> `Модель страницы`):** Изменение `$searchQuery` (с логикой debounce) передается в `Модель страницы`.
3.  **Запуск поиска (`Модель страницы` -> `Search Results Model`):** `Модель страницы` отправляет событие **"Дергаем api"** в модель `Search Results Model`.
4.  **Вызов API (`Search Results Model` <-> `searchDocumentsApi`):** `Search Results Model` вызывает `effect` `searchDocumentsApi`. Пока запрос выполняется, стор `$isSearchLoading` находится в состоянии `true`. После получения ответа данные записываются в `$searchResults`.
5.  **Отображение результатов (`Search Results UI`):** Компонент результатов поиска, подписанный на сторы модели, отображает либо загрузчик, либо список найденных документов.

### 3. Выбор документа из результатов

1.  **Выбор документа (`Search Results Model` -> `Модель страницы`):** Пользователь кликает на один из найденных документов. Модель результатов отправляет в `Модель страницы` событие **"Select doc"** с информацией о выбранном файле.
2.  **Открытие в редакторе (`Модель страницы` -> `Модель маркдаун`):** `Модель страницы` обрабатывает это событие и через событие **"Открываем документ"** передает данные в модель редактора Markdown, который загружает и отображает контент файла.
3.  **Синхронизация с деревом (`Модель страницы` -> `Document Tree UI`):** Одновременно `Модель страницы` через событие **"Храним выбранный документ"** сообщает модели дерева о текущем выборе. Это необходимо, чтобы после закрытия поиска в дереве был подсвечен нужный файл.

### 4. Завершение поиска (очистка)

1.  **Очистка поля (`Search` (Close) -> `Модель страницы`):** Пользователь нажимает кнопку "очистить" в поле поиска. Это инициирует событие **"Close"** в `Модели страницы`.
2.  **Сброс состояния (`Модель страницы` -> `Search Results Model`):** `Модель страницы` отправляет два события в модель результатов поиска:
    - **"Чистим стор листа"**, чтобы обнулить список найденных документов.
    - **"Закрываем компонент"**, чтобы скрыть UI результатов поиска.
3.  **Обновление дерева (`Модель страницы` -> `Document Tree UI`):** `Модель страницы` инициирует событие **"После закрытия обновляем дерево"**. Это делает компонент `Document Tree UI` снова видимым. Так как модель дерева уже знает о выбранном документе (из шага 3.3), она корректно отобразит его подсветку.
